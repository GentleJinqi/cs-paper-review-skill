# Legacy Reconciliation

Observed 2026-07-28. Public baseline:
`2810ea62cdc24bed48b8079fab02b4cb684c0238`.

The baseline contained two README files and 19 portable payload files, with no
tag and no root licence. The redesign preserves mechanisms, not legacy file
shape or runtime topology.

## Generalisable Mechanism Categories

- review-only intake and immutable input lineage;
- source/PDF integrity and explicit partial or blocked outcomes;
- current first-party venue criteria as an optional profile;
- independent initial assessment before process-aware checks;
- evidence-anchored canonical findings, adjudication, dissent, and closure;
- phase-aware placeholders and separate scientific, author-data, and
  packaging risks;
- delta lineage and repair-introduced-risk checks;
- completion based on evidence obligations rather than reviewer count.

## Assumptions To Supersede

- fixed strict/standard tiers and reviewer rosters;
- fixed task or subagent counts as a proxy for rigor;
- unspecified venue defaulting to TMLR;
- overlapping severity and impact scales;
- legacy close-agent APIs and historical agent IDs;
- corpus size or repeated votes as scientific evidence;
- unbounded “review until dry” completion.

## Historical Evidence Boundary

The legacy workflow supplies useful behavioural obligations but lacks exact
model, effort, prompt, tool-schema, token, host, and runtime provenance. It
therefore does not establish GPT-5.6 Sol Ultra compatibility, numerical
recall/precision, cross-venue fidelity, acceptance probability, or superiority
of any agent topology.

Project paths, manuscript content, private findings, run hashes, and review
history are intentionally excluded from this public record.
